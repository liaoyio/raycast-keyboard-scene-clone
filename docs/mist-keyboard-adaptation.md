### 缓存与交互

实时材质使用五张独立的 2048 × 2048 线性 EXR：

| 文件 | 输入 | 导出字节数 |
| --- | --- | --- |
| `texture-cap-off.exr` | 松开键帽的熄灯受光与原字样外观 | 14,466,258 |
| `texture-cap-pressed-off.exr` | 压下 0.16 模型单位的键帽熄灯外观 | 14,479,098 |
| `texture-static-off.exr` | 外壳、轴体、旋钮、侧条等静态结构 | 6,476,907 |
| `texture-white-raw.exr` | 每个松开键帽仅受自身椭圆灯照明的白光贡献 | 14,544,071 |
| `texture-white-pressed-raw.exr` | 每个压下键帽仅受自身椭圆灯照明的白光贡献 | 14,548,261 |

松开和压下两态共用原 UV，以 `clamp(actualDepth / 0.16, 0, 1)` 插值。这里的键程来自共享渲染器实际阻尼位置，不用按键布尔值切换图像。G 的预检查发现，两态可见顶盖熄灯响应有明显差异，因此不能只更新白光而复用松开熄灯图。静态结构始终只使用自己的熄灯缓存。

完整烘焙使用 Cycles Metal、64 samples。为保持原 2048 texel 密度，烘焙副本将每帽 UV 的整数像素窗口移到独立小图，再回贴原图；最终工程不保存该临时 UV 变换。G 的加速预检查中，往返误差约 0.0000166 像素，光芯能量与完整图烘焙相差 0.62%，处于该次采样噪声范围；这不是逐位相同的声明。

原 UV 有 86 个内顶盖面像素别名，涉及 Enter、Backspace、Backslash 与 IconGrid。172 次双面射线检查均被同键帽外表面遮挡，没有可直视外顶面或字样冲突。四类键帽缓存采用相同的 ASCII 键名先写入规则，不移动 UV。`uv-overlap-audit.json` 和 `uv-overlap-visibility.json` 保存在制作目录；该规则只适用于当前固定相机和原 UV。

静态缓存另有两处 UV 限制。轴下平面 component24 的顶面、底面和四侧共用同一 UV，普通整件烘焙会让隐藏面的暗响应覆盖可见顶面，形成黑网格。修复在临时 bake UV 中只选可见顶面，保留原材质采样 UV 和全部物理几何，再将真实受光回贴原图。外壳 component18 的部分倒角 UV 退化或窄于一个纹素，没有有效烘焙种子；这些可见面另以临时三角岛取得真实熄灯响应，补足原 UV 的双线性采样支持。两项处理都不改最终几何或 UV，也不以白色常量填充。

原 UV 无法独立表达 component24 隐藏侧面与底面，component18 共用采样支持也只能保留可见面的平均响应。当前缓存以固定展示相机为准；新增观察角度前需重做 UV 与光路校验，不能把它当作可任意旋转的物理材质。

导出脚本以 ZIP float32 EXR 保留能量，并预翻行抵消当前 Three `EXRLoader` 的倒序解码；运行时使用 HalfFloat、`LinearSRGBColorSpace` 和 `flipY=false`。`texture-frosted-base.png` 是源外观预览，退出实时输入；原 Base／Light PNG 保留。五张 HalfFloat 图各约 32 MiB，桌面合计约 160 MiB CPU 缓存及 160 MiB GPU 纹理。Canvas 卸载会释放 GPU 上下文，成功解码的 CPU 图像由 `useLoader` 缓存保留；移动端仍只加载静态回退。

显示响应先在线性空间相加，再逐通道处理：

```text
off = mix(restOff, pressedOff, pressMix) × 1
raw = mix(restWhite, pressedWhite, pressMix)
energy = raw × cornerMask × envelope × 4 × (1 + localRipple)
F(x) = clamp(x × (2.51x + 0.03) / (x × (2.43x + 0.59) + 0.14), 0, 1)
display = F(off + energy)
```

熄灯和白光共用该响应；减少能量时，低能量柔光先退，白芯最后收回。旧版 `(0.96 - off)` 上限不再使用。Canvas 为 `flat`，不额外叠加 Three.js tone mapping；该函数不等同于 Three.js ACES 的精确实现。

当时的脚本默认读取上述仓库外的 `mist-diffused-white-light.blend`。输出目录需有 `keyboard.glb` 和两张原 PNG 用于校验，默认写入 `public/assets/mist`，也可通过 `--output-dir` 指定。键帽基底取工程中 `Frosted cap base / original UV` 已打包的 sRGB PNG 字节；原 `White off / reference ambient` 保留静态外壳外观。该脚本不保存 `.blend`，导出前后核对输入文件哈希；这些选项不再是当前仓库可执行的接口。

Blender 展示坐标 `(x, y, z)` 对应网页 `(x, z, -y)`；网页 UV 为 `(u, 1 - vBlender)`。当前 `EXRLoader` 在解码时倒序写行，因此导出 EXR 已预翻行，运行时不能再次翻转 V 或复用原 PNG 的 sRGB 配置。导出头保存 21 个跨行探针，网页测试应使用 Three `EXRLoader` 的 FloatType 解码逐值核对；运行时默认 HalfFloat，仍须保留大于 1 的线性能量。早期缓存曾验证 26 个探针，最大 HalfFloat 舍入误差约 0.003906，仅用于历史对照。

`mist-light-mask` 是 Blender 的 `FLOAT / CORNER` 属性。同一 UV 甚至同一个索引顶点，可能同时属于允许透光和需要遮光的表面，不能转成普通 UV 遮罩图。bin 开头的 4 字节是小端 uint32 JSON 长度，随后为 UTF-8 JSON，补齐至 4 字节边界后存放小端 Float32 数组。文件头的 `keys[].offset` 与 `count` 均以 Float32 元素为单位。

`parseMistWhiteMask` 检查版本、83 键、连续范围及数值；`createMistWhiteLightScene` 克隆场景，仅将键帽几何 `toNonIndexed()` 并附加 `whiteMask`。展开保持原三角角点位置、UV 和法线；静态几何继续共享原资源。新几何由 Mist 场景卸载时释放，加载器缓存和原几何不在此处释放。导出时已逐角点比较全部 84 个网格，位置误差为 0，UV 最大误差约 2.98e−8。

### 白光合成与灯株坐标

按用户要求，“环境照明权重”默认 0.9、范围 0.1–1，“白光贡献增益”默认 4、范围 0–16。键帽使用同材质烘焙的柔光 Base，静态结构使用原 Base，两者均按 sRGB 解码再乘网页环境权重。`createMistMaterial` 的可选 `capBase` 只替换交互键帽，每个材质建立独立 `uBaseMap`，避免修改共享 uniform 后把静态外壳也贴成键帽 UV 图集。原 PNG 字节不变，没有用 gamma 或曝光补偿贴图。较低环境 0.16 和 0.55 的中间方案仅作历史记录。

材质逐 RGB 通道计算：

```text
off = sRGBDecode(Base) × ambient
energy = max(rawWhite, 0) × cornerMask × interactive × envelope × gain × (1 + ripple)
display = (off + (0.96 - off) × (1 - exp(-0.9 × energy))) × dim
```

默认 `ambient=0.9`、`gain=4`，按键压暗比例为 0。包络先控制线性能量，再压缩显示亮度，余光中的白芯随能量下降收小。前侧底边和底面沿用 Blender 的角点遮罩；静态结构的 `interactive=0`、缺省 `whiteMask=0`，只显示 `off`，轴体、外壳和彩色侧面指示灯不参与动态白光。当前材质不使用 Gaussian 灯斑、轴心遮挡近似或 bloom。

`getMistLampPosition`、模型 extras 和布局清单使用同一校准：

```text
pitch = 1.899807
lampPosition = [bounds.center.x, 0.41, bounds.center.z - 0.245 × pitch]
lampRadiiXZ = [0.155 × pitch, 0.055 × pitch]
            = [0.294470085, 0.104489385]
```

这些值以模型单位表示。全部 83 个位置和尺寸已与 Blender 独立椭圆灯面核对，最大坐标差约 8.35e−7。长键使用相同半轴，不随键帽宽度拉伸。灯株本体位于内腔，向上受到内外顶盖覆盖；用户看到的是透过雾透键帽的光芯和外围散射，均来自烘焙缓存。

### 半秒包络与网页局部涟漪

正常模式默认起亮 2/30 秒、消退 13/30 秒，无额外峰值停留。`startMistLight` 记录当前亮度并重新开始本键包络；`advanceMistLight` 用余弦缓入缓出完成一次亮灭，长按不锁峰。长按策略和余光中重按续起是网页交互决定，不能标为 `IMG_1600.MOV` 的实测结果。减少动画模式下，白灯直接跟随按下与松开，涟漪关闭。

`scene.tsx` 为每键记录 `performance.now()`，用实际经过的时间推进白灯，不使用共享渲染器截断后的帧间隔。这样低帧率和 demand 模式的空闲间隔不会拖长半秒脉冲；键帽位移仍沿用共享阻尼。重按前先补算自上次绘制以来的时间，再从此刻亮度续起，避免把旧帧的余光当成当前值。

减少动画状态优先于“脉冲已结束”的判断。即使正常模式的半秒灯效已经熄灭，仍按住的键在切入减少动画后也会显示亮度 1，松开后为 0；退出减少动画时保留可继续消退的状态，避免停在亮灯状态。

按用户最新要求，网页在当前灯株周围增加一圈局部涟漪。“灯株涟漪强度”默认 0.6、范围 0–1.5。Shader 以灯株 XZ 半轴归一化距离，在半秒包络内将环半径从 0.25 扩至 2.35，再乘渐隐权重。涟漪只调制原缓存已有的白光能量，并受本键包络和表面遮罩约束；不会另生成光斑或触发邻键。各键余光和涟漪可以独立重叠。

`MIST_RENDER_PROFILE` 提供 `createMaterial`、`onPress`、`lampPosition`；`scene.tsx` 结合调参补充 `advanceLight`。共享 `Air75AnsiKeyboard` 在存在 Mist 的 `onPress` 时只启动该键动画，不写入默认整板脉冲数组。Air75 未使用这组 hooks，保留原有波纹行为。

白光仍是固定 UV 光路缓存，没有随键程逐帧重算折射。柔光材质用原烘焙 Base 拟合外观，没有恢复实测 albedo，因此不能称为完全复现实物。修改灯位、材质或烘焙视角后，需要重新烘焙。网页新增的局部涟漪不在 Blender 成片中。

产品舞台固定为 `#eef0f1` 浅雾白。标题为 26–32px，文案“白光透过雾透键帽，柔和亮起。”为 14px，下方交互提示与演示入口为 12px；移除早期英文眉题、大字号标题和提示胶囊。原 400px 舞台、首帧显示、相机投影和移动静态回退保留，全局明暗主题不修改产品画面。

动画检查还发现，直接混合已经压缩的熄灯图和亮灯图，会使余光过早变灰。视频中的白芯在消退阶段仍接近白色，主要变化是范围缩小。因此新材质把包络放在显示压缩之前，分别计算 RGB 通道：

```text
energy = rawWhite × mask × envelope × 8
display = off + (0.96 - off) × (1 - exp(-0.9 × energy))
```

`off` 是线性环境外观，`rawWhite` 是未压缩的白光烘焙贡献。原半秒包络仍控制能量衰减。各通道独立计算，保留烘焙材质产生的透光差异；静态结构只使用 `off`。这次没有修改全局曝光、gamma 或灯株几何。

这版使用固定光路缓存。改变材质、灯位或相机后需要重新烘焙，不能继续沿用当时的白光贡献。前版工程保留用于对照；完成早期亮度修正后，同日曾将缓存、播放器 MP4 和海报接入网页。
